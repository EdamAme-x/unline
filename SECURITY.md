# Security Notes

This project is a self-hosting wrapper around third-party LINE client assets. Treat generated files as untrusted upstream code.

Default protections:

- Fixed upstream proxy targets only.
- Host header allowlist.
- Origin allowlist for proxy CORS handling.
- `Cookie` and `Authorization` stripping by default.
- Upstream `Set-Cookie` and `Access-Control-*` response stripping.
- Strict response headers for the web client.
- Optional Basic auth with a salted PBKDF2-SHA256 hash generated by `unline setup`.
- Generated assets, certificates, `.env` files, CRX downloads, and ZIP files are blocked from normal git tracking.
- `gitleaks` is used by hooks for secret scanning.

Before exposing outside localhost:

1. Serve behind HTTPS.
2. Set `UNLINE_ALLOWED_HOSTS` to the exact public hostname.
3. Keep `UNLINE_FORWARD_COOKIES=false`.
4. Keep `UNLINE_FORWARD_AUTHORIZATION=false` unless verified necessary.
5. Re-run `go run ./cmd/unline verify --assets ./www` after every regeneration.
6. Use `go run ./cmd/unline setup --out .env` and load the generated Basic auth hash.
